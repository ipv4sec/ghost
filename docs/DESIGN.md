## 1. 产品概述

### 1.1 定位

一个基于 **115 生活开放平台** 的网盘文件浏览 App（Flutter，Android 优先）。核心能力：
















































































































































































































































- **扫码授权登录**（OAuth 2.0 + PKCE 设备码模式，无需后端）
- **浏览网盘文件**（目录导航、分页加载、排序）
- **搜索文件**
- **查看用户信息与容量**

> 参考图实际是 Amaze 文件管理器的截图（蓝色顶栏 + 路径统计栏 + 圆形图标列表），本设计以其为主要视觉基调，结合 115 开放平台的实际数据字段做了网盘化改造。**如果你更想要 115 官方 App 的风格（顶部用户区+分类宫格），见 §9 备选方案，可切换。**

### 1.2 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Flutter 3.24 (Material 3) | 现有项目骨架 |
| 状态管理 | ChangeNotifier + provider（或纯 setState 起步） | 页面少，避免过度设计 |
| 网络 | http 包 | 文档均为 REST/JSON |
| 二维码 | qr_flutter | 扫码授权页生成设备二维码 |
| 本地存储 | shared_preferences | 持久化 token（明文，见 §8.2 安全注意） |
| 加密 | crypto (sha256) | PKCE code_challenge 计算 |
| 图片 | cached_network_image | 头像/视频缩略图（`v_img`/`thumb` 字段） |

### 1.3 页面总览（信息架构）

## 3. 页面详细设计

### 3.1 登录页 LoginPage

```
┌────────────────────────────┐
│                            │
│         [App Logo]         │
│         妖妖舞 网盘          │
│                            │
│   ┌────────────────────┐   │
│   │                    │   │
│   │    设备二维码 (QR)    │   │  ← qr_flutter 渲染 data.qrcode
│   │                    │   │
│   └────────────────────┘   │
│                            │
│    请使用 115 App 扫码授权    │  ← 状态文案，随轮询变化
│                            │
│      [ 刷新二维码 ]          │  ← 过期后可重开一轮
└────────────────────────────┘
```

**状态机**（对应轮询接口 `data.status`）：

| 状态 | 文案 | 行为 |
|---|---|---|
| 加载中 | 正在获取二维码… | 调 `/open/authDeviceCode` |
| 等待扫码 | 请使用 115 App 扫码授权 | 长轮询 `qrcodeapi.115.com/get/status/` |
| 已扫码待确认 | 扫码成功，请在手机上确认 | 继续轮询 |
| 确认授权 | 授权成功 | 调 `/open/deviceCodeToToken`，存 token，进主页 |
| 二维码失效 (state=0) | 二维码已失效 | 显示"刷新二维码"按钮 |
| 网络错误 | 网络异常，点击重试 | 同上 |

**技术要点**：
- PKCE：`code_verifier` 随机 64 字符（A-Za-z0-9-._~），`code_challenge = url_safe(base64(sha256(verifier)))`（去 `=` 填充）
- 长轮询超时（约 30s）不算失败，立即重新发起
- 需要用户在设置页填自己的 `client_id`（AppID），首次启动若无配置则先弹配置入口

### 3.2 文件页 FilesPage（Tab1，核心页）

#### 3.2.1 顶栏

```
┌──────────────────────────────────────────┐
│ ←  文件         🔍   ▦/☰   ⋮   │  ← 蓝底白字
└──────────────────────────────────────────┘
```

| 元素 | 行为 |
|---|---|
| 返回箭头 | 根目录时隐藏；否则返回上级目录（出栈） |
| 标题 | 根目录显示"文件"；子目录显示当前文件夹名 |
| 搜索图标 | 跳转 SearchPage |
| 视图切换 | 列表 ⇄ 网格，记忆到本地 |
| 更多 ⋮ | 弹出菜单：排序、刷新、多选（v0.2） |

#### 3.2.2 路径 + 统计栏

```
┌──────────────────────────────────────────┐
│ / 全部文件 / 音乐 /无损          ≥ │  ← 可点面包屑
│ 12个文件夹，34个文件                       │
└──────────────────────────────────────────┘
```

- 面包屑数据源：列表接口返回的 `path[]`（父目录树）
- 统计文案：`文件夹数 = count 中的目录项`，文件数同理（本地计数）
- 加密目录（`isp=1`）整行加 🔒 角标，点击弹"请到官方 App 输入提取码"提示

#### 3.2.3 文件列表（列表视图）

```
┌──────────────────────────────────────────┐
│ (📁) 无损音乐专区            ⋮ │
│      2024-05-12 14:30 │ 12项           │ ← 文件夹：时间 | 子项数
├──────────────────────────────────────────┤
│ (🎬) 《沙丘2》4K.mkv          ⋮ │
│      2024-05-12 14:30 │ 24.5 GB       │ ← 文件：时间 | 大小
├──────────────────────────────────────────┤
│ (📄) 年度总结.docx             ⋮ │
│      2024-05-12 14:30 │ 1.2 MB        │
└──────────────────────────────────────────┘
```

- 左侧 40dp 圆形类型图标（视频/图片用缩略图，圆形裁剪）
- 主文字：文件名（`fn`），最多 1 行省略
- 副文字：`upt 格式化时间` │ `fs 格式化大小`（文件夹显示子项计数，需要时懒加载）
- 星标文件（`ism=1`）名称后加 ⭐ 小标
- 行尾 ⋮ → 底部动作弹层（见 3.2.6）

#### 3.2.4 文件网格（网格视图）

2 列卡片：上 96dp 缩略图/类型图标区 + 下文件名（2 行省略）+ 时间。文件夹卡片显示封面 `fco`（若有）。

#### 3.2.5 分页与加载

- 首页 `limit=50`，滚到底部自动加载下一页（`offset += 50`），列表尾显示 loading 圈
- 下拉刷新：RefreshIndicator 重新拉当前目录
- 排序默认：`o=user_ptime, asc=0`（上传时间降序）；文件夹始终置顶（`custom_order=2`）
- 加载失败显示错误占位 + 重试按钮

#### 3.2.6 文件动作弹层（点 ⋮ 或长按）

| 动作 | 实现接口 | 说明 |
|---|---|---|
| 详情 | `GET /open/folder/get_info`（按ID） | 弹层展示：名称/大小/时间/SHA1/fid |
| 播放（仅视频） | `GET /open/video/play` | 进入播放页，见 §3.7 |

### 3.7 视频播放页 VideoPlayerPage（新增，v0.1 范围）

```
┌──────────────────────────────────────────┐
│ ←                                     ⋮  │  ← 透明浮层于视频上
│                                          │
│            [视频画面 16:9]                 │
│                                          │
├──────────────────────────────────────────┤
│  清晰度: [原画|1080P|超清|高清|标清]        │  ← definition_list

```

- 入口：文件列表/搜索点视频文件 → `GET /open/video/play?pick_code=…`
- 播放器：video_player（HLS/MP4），失败提示该视频暂未完成转码
- 清晰度切换：`video_url[].definition` 列表，切换后从当前进度继续
- 音轨切换：播放地址后加 `?audio_track=N`（键取 multitrack_list）
- 进度记忆：进入时 `GET /open/video/history` 取 `time` 续播；退出/暂停时 `POST /open/video/history` 上报（time + watch_end）

## 4. 数据模型与接口映射

### 4.1 模型

```dart
class FileItem {
  final String fid;        // 文件ID
  final String pid;        // 父目录ID
  final String name;       // fn
  final bool isDir;        // fc == "0"
  final int size;          // fs
  final DateTime? mtime;   // upt
  final String ico;        // 后缀
  final int typeId;        // 文件类型 1-7（本地按后缀推断）
  final String? thumbUrl;  // v_img / thumb / fco
  final bool starred;      // ism == "1"
  final bool encrypted;    // isp == 1
  final String sha1;
}

class UserInfo {
  final int userId; final String name; final String avatar;
  final int usedBytes, totalBytes; final String usedText, totalText;
  final String vipName; final int vipExpire; final bool tpRights;
}

class TokenStore { accessToken, refreshToken, expiresAt, userId }
```

### 4.2 接口清单

| 用途 | 方法 + 路径 | 关键参数/响应 |
|---|---|---|
| 设备码 | POST `passportapi.115.com/open/authDeviceCode` | client_id, code_challenge(sha256) → uid/time/qrcode/sign |
| 轮询扫码 | GET `qrcodeapi.115.com/get/status/` | uid,time,sign → status 1/2 |
| 换 token | POST `passportapi.115.com/open/deviceCodeToToken` | uid, code_verifier → access/refresh/expires_in |
| 刷新 token | POST `passportapi.115.com/open/refreshToken` | refresh_token → 新凭证（60s 内勿重复） |
| 文件列表 | GET `proapi.115.com/open/ufile/files` | cid,limit=50,offset,o,asc,custom_order=2 |
| 搜索 | GET `proapi.115.com/open/ufile/search` | search_value,limit=50 |
| 用户信息 | GET `proapi.115.com/open/user/info` | — |
| 文件详情 | GET `proapi.115.com/open/ufile/file_info` | file_id |
| 下载地址 | GET `proapi.115.com/open/ufile/download_url` | file_id（GET/POST 按文档） |
| 重命名/更新 | POST `proapi.115.com/open/ufile/update` | file_id + file_name |
| 删除 | POST `proapi.115.com/open/ufile/delete` | file_id（回收站） |

### 4.3 Token 生命周期（拦截策略）

```
任一业务请求返回 code 40140125 / 40140126
  → 单飞刷新（防并发重复刷新触发 40140117）
  → 成功：重放原请求
  → 失败且 40140116/40140119/40140120/40140137（终态）：
       清 token → 跳登录页（提示"授权已失效，请重新扫码"）
```

## 8. 风险与待确认项 ⚠️

### 8.1 需要你确认的问题

1. **视觉基调**：当前按参考图（Amaze 蓝色文件管理器风格）设计。是否改为 115 官方风格（顶部用户卡片+九宫格分类入口+推荐文件流）？或 Material You 动态取色？
2. **平台范围**：仅 Android？是否需要 Windows 桌面（Flutter 项目已含 windows 目录吗——当前未见，默认不做）？
3. **AppID**：扫码登录必须有自己的 `client_id`（open.115.com 申请）。是内置你的 AppID，还是保留"我的→AppID 设置"让用户自填？内置的话请提供。
4. **删除功能**：v0.1 就开放删除，还是先只读（浏览+搜索）更稳妥？
5. **视频播放**：是否需要在 v0.3 加在线播放（拿到 play_url 后用 video_player/外部播放器打开）？

### 8.2 安全注意

- token 用 shared_preferences 明文存储仅是 v0.1 权宜；正式版应迁移 `flutter_secure_storage`
- `client_id` 若内置，注意不要连同用户 token 一起提交到公开仓库
- 遵守《开发须知》：不缓存用户文件内容到本地磁盘（缩略图内存缓存除外）

### 8.3 已知技术风险

- 长轮询接口在弱网下超时行为需真机验证（超时 ≠ 失败，自动重发）
- 列表接口 `count` 是"当前目录文件数"，与文件夹数需前端自行统计（响应含 `sys_count` 系统目录数）
- 下载地址接口可能有有效期与防盗链，复制到剪贴板的方式对大文件体验一般，v0.3 考虑系统下载器接管
